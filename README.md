## 📖 این پروژه چه می‌کند؟

پنل مدیریتی سبکی که روی [Tor-ML](https://github.com/icubaby/Tor-ML) سوار می‌شود.

Tor-ML روی سرور ۵۰ نمونه‌ی مستقل Tor اجرا می‌کند که هرکدام به یک کشور خاص قفل شده و روی یک پورت SOCKS محلی گوش می‌دهد (`127.0.0.1:48180` تا `48229`). این پنل لایه‌ی Xray و nginx را می‌سازد که ترافیک هر کاربر را به پورت درست می‌فرستد.

نتیجه: **برای هر کاربر یک لینک ساب می‌سازید و او ۵۰ سرور با ۵۰ لوکیشن مختلف در کلاینتش می‌بیند.**

## 🏗 معماری

```
┌──────────────── Railway (این پنل) ─────────────────┐
│  مدیریت کاربر · ساخت ساب · تولید کانفیگ            │
│  ترافیک پروکسی از اینجا رد نمی‌شود                  │
└───────────────────────┬────────────────────────────┘
                        │  agent.sh هر ۶۰ ثانیه می‌کشد
                        ▼
┌──────────────── VPS شما (Ubuntu/Debian) ───────────┐
│                                                    │
│  کلاینت ──TLS/443──► nginx                         │
│                        │                           │
│         /ws/de ────────┼──► Xray :10001 ──► :48180 │ 🇩🇪
│         /ws/tr ────────┼──► Xray :10002 ──► :48181 │ 🇹🇷
│         /ws/us ────────┼──► Xray :10003 ──► :48182 │ 🇺🇸
│         ...            │         ...          ...  │
│         /ws/tn ────────┴──► Xray :10050 ──► :48229 │ 🇹🇳
│                                        └─ Tor-ML ─┘│
└────────────────────────────────────────────────────┘
```

**چرا این شکل؟** Xray برای هر مسیر WebSocket یک inbound جدا لازم دارد، و nginx بر اساس path مسیریابی می‌کند. هر ۵۰ inbound داخل **یک** پروسه‌ی Xray هستند (inbound در Xray سبک است)، پس مسیریابی به یک نگاشت ساده‌ی `inboundTag → outboundTag` خلاصه می‌شود.

**چرا یک UUID به‌جای ۵۰ تا؟** اگر هر لوکیشن UUID جدا داشت، ۱۰ کاربر می‌شد ۵۰۰ کلاینت در کانفیگ سرور. با تفکیک بر اساس path، اضافه‌کردن کاربر یعنی اضافه‌کردن **یک** هویت.

## 🚀 راه‌اندازی

### گام ۱ — پنل روی Railway

1. این ریپو را به Railway وصل کنید (New Project → Deploy from GitHub repo).
2. متغیرهای محیطی را ست کنید:

```bash
ADMIN_PASSWORD=یک-رمز-بلند
SESSION_SECRET=$(openssl rand -hex 32)
SYNC_KEY=$(openssl rand -hex 24)
DATA_DIR=/data
```

3. **یک Volume روی `/data` وصل کنید.** بدون این، با هر دیپلوی همه‌ی کاربران پاک می‌شوند.
4. یک دامنه بگیرید (Settings → Networking → Generate Domain).

### گام ۲ — تنظیمات پنل

وارد پنل شوید و در بخش «تنظیمات سرور» آدرس دامنه یا آی‌پی **سرور Xray** خودتان را وارد کنید — نه آدرس پنل.

> ⚠️ دامنه‌ی `*.up.railway.app` آدرس **پنل** است. کانفیگ‌ها باید به سرور خودتان اشاره کنند، چون Tor-ML پورت‌های SOCKS را فقط روی `127.0.0.1` باز می‌کند و Xray باید روی همان ماشین باشد.

### گام ۳ — نصب روی سرور

```bash
git clone https://github.com/jack22Jqck211/panel
cd panel

sudo bash deploy/install.sh \
  --panel  https://your-panel.up.railway.app \
  --key    YOUR_SYNC_KEY \
  --domain srv.example.com \
  --email  you@example.com
```

اسکریپت این کارها را می‌کند: نصب Tor-ML و Xray و nginx، گرفتن گواهی TLS با certbot، کشیدن کانفیگ از پنل، و نصب یک تایمر systemd که هر ۶۰ ثانیه هم‌گام‌سازی می‌کند.

### گام ۴ — روشن کردن لوکیشن‌های Tor

```bash
# همه ۵۰ لوکیشن (حدود ۱ تا ۱.۵ گیگابایت رم لازم دارد)
sudo /opt/xray-panel-agent/tor-start.sh all

# یا فقط چند لوکیشن
sudo /opt/xray-panel-agent/tor-start.sh 1,2,3,9,10

# وضعیت
sudo /opt/xray-panel-agent/tor-start.sh status
```

تست یک خروجی:

```bash
curl --socks5-hostname 127.0.0.1:48180 https://api.ipify.org
```

### گام ۵ — ساخت کاربر

در پنل، نام کاربر را بزنید و (اختیاری) یک آی‌پی تمیز. لینک ساب را به او بدهید. تمام.

## 🔗 قالب‌های ساب

| آدرس | خروجی | مصرف |
|---|---|---|
| `/sub/<token>` | تشخیص خودکار | مرورگر HTML می‌گیرد، کلاینت base64 |
| `/sub/<token>?b64=1` | base64 | V2rayNG · v2rayN · NekoBox |
| `/sub/<token>?raw=1` | لیست خام `vless://` | دیباگ و کپی دستی |
| `/sub/<token>/view` | صفحه‌ی HTML | دیدن ۵۰ کانفیگ با پرچم |
| `/sub/<token>?format=clash` | YAML | Clash-Meta · Mihomo |

تشخیص خودکار بر اساس هدر `Accept` است. چون بعضی کلاینت‌ها `*/*` می‌فرستند، آدرس‌های صریح هم وجود دارند تا هیچ‌وقت خروجی اشتباه نگیرید.

هدرهای `Subscription-Userinfo`، `Profile-Update-Interval` و `Profile-Title` ست می‌شوند تا کلاینت حجم و انقضا را درست نشان دهد.

## 🧼 آی‌پی تمیز چطور کار می‌کند؟

وقتی آی‌پی تمیز را وارد می‌کنید، کلاینت به آن آدرس وصل می‌شود ولی `sni` و هدر `Host` روی دامنه‌ی واقعی می‌مانند:

```
vless://uuid@104.17.0.1:443?type=ws&security=tls&sni=srv.example.com&host=srv.example.com&path=/ws/de
        └── آی‌پی تمیز ──┘                          └────── دامنه‌ی واقعی ──────┘
```

> ⚠️ این فقط وقتی کار می‌کند که دامنه‌ی شما **از یک CDN مثل Cloudflare رد شود**. اگر دامنه مستقیم به آی‌پی سرور اشاره کند، آی‌پی تمیز دلخواه شما به سرور بی‌ربطی وصل می‌شود.

## ⚙️ متغیرهای محیطی

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `ADMIN_PASSWORD` | تصادفی | رمز ورود پنل. اگر ست نشود، هر ری‌استارت عوض می‌شود |
| `SESSION_SECRET` | تصادفی | کلید امضای کوکی. اگر ست نشود، هر ری‌استارت لاگ‌اوت می‌شوید |
| `SYNC_KEY` | — | کلید مشترک برای `/api/sync`. تا ست نشود، ایجنت کار نمی‌کند |
| `DATA_DIR` | `/data` یا `./data` | محل ذخیره‌ی کاربران. باید Volume باشد |
| `PORT` | `8080` | پورت گوش‌دادن. Railway خودش ست می‌کند |

## ⚠️ محدودیت‌های واقعی

اینها را قبل از استفاده بدانید:

1. **Xray باید روی همان سرور Tor-ML باشد.** Tor-ML پورت‌های SOCKS را فقط روی `127.0.0.1` باز می‌کند. این محدودیت معماری است و راه دور زدنِ امنی ندارد.

2. **رم.** README خود Tor-ML رم ۵۱۲ مگابایت را کافی می‌داند که برای اجرای هم‌زمان همه‌ی ۵۰ نمونه خوش‌بینانه است. هر نمونه‌ی Tor حدود ۲۰ تا ۴۰ مگابایت می‌گیرد. روی سرور کمتر از ۲ گیگ، زیرمجموعه‌ای از لوکیشن‌ها را روشن کنید.

3. **کشورهای کم‌رله.** برای SC، TN، CR، MD و مشابه، Tor با `StrictNodes 1` ممکن است هیچ مدار خروجی پیدا نکند. محدودیت شبکه‌ی Tor است، نه باگ کانفیگ.

4. **سرعت.** ترافیک از Tor رد می‌شود: تأخیر بالا، سرعت پایین. برای ویدیو مناسب نیست.

5. **حجم مصرفی شمارش نمی‌شود.** حجم و انقضا در ساب اعلام می‌شوند و انقضا اعمال می‌شود، ولی پنل ترافیک را اندازه نمی‌گیرد. برای شمارش واقعی به Xray stats API نیاز است.

6. **توکن ساب یک راز است.** لینک ساب طبق ماهیتش بدون لاگین سرو می‌شود. هرکس لینک را داشته باشد دسترسی دارد؛ از دکمه‌ی «توکن نو» برای باطل کردن استفاده کنید.

7. **یک پروتکل در هر زمان.** VLESS یا VMess. این عمدی است: اگر ساب چیزی را تبلیغ کند که سرور قبولش ندارد، کاربر با خطای مبهم روبه‌رو می‌شود.

## 🧪 توسعه و تست

```bash
# اجرای محلی
ADMIN_PASSWORD=test go run .

# تست‌های واحد
go test ./...

# تست سرتاسری، شامل اعتبارسنجی با بایناری واقعی Xray
bash scripts/e2e.sh /path/to/xray
```

`scripts/e2e.sh` پنل را بالا می‌آورد، از طریق HTTP مثل یک مرورگر و یک کلاینت با آن کار می‌کند، و کانفیگ تولیدشده را با `xray -test` اعتبارسنجی می‌کند. تست‌های ساختاری نشان می‌دهند کانفیگ شکل درستی دارد؛ فقط `xray -test` ثابت می‌کند خود Xray قبولش می‌کند.

### اعتبارسنجی nginx

کانفیگ nginx در تست‌های Go ساختاری بررسی می‌شود (تعادل آکولادها، وجود هر ۵۰ بلوک، درستی نگاشت پورت‌ها، وجود هدرهای WebSocket). اعتبارسنجی با خود nginx در `agent.sh` انجام می‌شود: قبل از هر ریلود، `nginx -t` و `xray -test` اجرا می‌شوند و اگر خطا بدهند کانفیگ قبلی برگردانده می‌شود. یعنی یک کانفیگ خراب هرگز سرور را نمی‌خواباند.

### ساختار پروژه

```
main.go                  راه‌اندازی و مدیریت متغیرهای محیطی
internal/locations/      جدول ۵۰ کشور و نگاشت پورت‌ها
internal/store/          ذخیره‌سازی JSON با نوشتن اتمیک
internal/users/          ساخت کاربر، UUID، توکن
internal/proxyuri/       تبدیل یک کاربر به ۵۰ کانفیگ
internal/sub/            رندر base64 / raw / html / clash
internal/generate/       تولید کانفیگ nginx و Xray
internal/httpx/          روتر، احراز هویت، اندپوینت‌ها
web/                     رابط کاربری، با go:embed داخل بایناری
deploy/install.sh        نصب روی سرور
deploy/agent.sh          هم‌گام‌سازی و ریلود ایمن
deploy/tor-start.sh      روشن کردن لوکیشن‌های Tor
scripts/e2e.sh           تست سرتاسری
```
